# Meta attribution setup for review

Choose short, lowercase, non-personal identifiers and never include names, phone numbers or customer data. Example proposed first campaign: `pw-parenting-01`; example creatives: `pw-video-01` and `pw-image-01`. These are examples to approve, not live campaigns.

After approval, put the exact same campaign identifier in the public `CAMPAIGNS` array in `site-preview/analytics.js` and backend `ANALYTICS_CAMPAIGNS`; put the exact same creative identifiers in public `CREATIVES` and backend `ANALYTICS_CREATIVES`. The backend variables are comma-separated. These values are identifiers, not secrets. The public arrays and backend allowlists are empty by default and must be updated together before any activation.

Use a Meta destination URL such as `https://parentwise-ethiopia-full-website-preview.onrender.com/?utm_source=facebook&utm_medium=paid_social&utm_campaign=pw-parenting-01&utm_content=pw-video-01` (use `instagram` when that is the intended source). Use one approved `utm_content` per ad creative, and the same campaign for all creatives in that campaign. Do not include dynamic personal identifiers. The tracker accepts only its allowlisted values and stores first-touch attribution for the current consented browser tab. Missing or unapproved source is Other / unknown; missing or unapproved campaign/creative remains blank. A paid flag requires an approved campaign and a recognized paid medium. A click is not a purchase; only a separately verified payment is counted as a sale.

Meta placement and redirect behavior can change source tags, and browser blocking, consent refusal, tab changes, devices and network loss can leave attribution incomplete. Test actual approved links and both backend and public allowlists before any collection is enabled. Do not activate tracking or ads through this review branch.
